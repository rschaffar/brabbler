# Feature implementation contracts

Implementation reference moved from `AGENTS.md`; repository-relative code paths remain unchanged. Read the relevant section before modifying that area. Focused user guides and ADRs linked below retain their existing scopes.

### Personal scratchpads

- The top-bar **Notes** button opens a native modal above the current workspace: **Global** and **This session** plain-text editors are visible together (stacked at narrow widths). Closing/Escape restores trigger focus without stopping the agent, changing chat/Files/terminal selection or sending notes to the model. The global editor receives initial focus. Session notes require a saved, non-transient chat; new chats explain that the first message must be sent first.
- Global means this **Pi Web installation**, not one browser or project. Session notes are keyed by the saved session ID, so returning to a chat or moving its cwd retains them; forks/clones have independent IDs and do not inherit notes. Anyone with access to this server can access its notes under the ordinary web-auth boundary. These are not encrypted secret storage and do not grant file access or automatically enter agent context.
- Private version-1 JSON notes live under `~/.pi/agent/pi-web/scratchpads/` (or the configured agent directory); filenames are SHA-256 hashes of JSON-encoded scope IDs. `GET/PUT /api/scratchpad` validates scope and bounds notes to 100,000 UTF-16 code units, streamed update bodies to 1 MB. Each update compares a content revision under a stable pathname lock, then uses the shared private flushed atomic writer. Identical content is an idempotent acknowledgement, including after a lost response. Corrupt reads fail rather than replacing data with empty notes. Notes are retained after session deletion; no automatic garbage collection is added. Include this directory in backups.
- `ScratchpadController` retains one independent history/save owner per opened note while the page lives. Every edit immediately writes a same-tab `sessionStorage` recovery draft and starts a single-flight server write with no typing debounce; newer edits coalesce behind the request. Closing/switching does not cancel saves. **Saved to server** means acknowledged current text, not merely a local draft. Save/load failures retain text and expose Retry; unavailable local recovery is explicitly warned about. Per-tab recovery survives reload, not closing the browser tab; an unacknowledged write is not a promise of server persistence.
- Reopening/focus refreshes clean notes. A stale write or recovered stale draft shows the remote version without overwriting local text: explicit **Save my version** or **Use server version** resolves it, and another server advance can conflict again. Copy supports manual combination. Undo/redo is independent per editor, groups contiguous typing/deletion, and survives panel/session switching in the current page. Histories are bounded to 100 entries / roughly 2 million retained code units per note; reload restores text, **not history**. Clean external changes clear old local history. Choosing the server version is itself undoable.
- Core regressions cover serialized saves, pending undo, reload/lost-ack recovery, conflicts, scope isolation, request guards and private/corrupt storage. The appearance browser group adds independent desktop and 390×600 touch scenarios for native modal/focus/Escape, immediate persistence without blur, keyboard/buttons/history, scope/reload/conflict recovery and responsive geometry.

### Starred sessions
- Stars live in `~/.pi/agent/pi-web/starred-sessions.json`, not in session files or the browser's long-term storage. `POST /api/starred-sessions` applies idempotent per-ID set/unset changes under a file lock; legacy localStorage lists are imported as a union then removed only after success. A browser with an old, not-yet-imported list may reintroduce a previously removed star on its first visit.
- `useStarredSessions` shares one browser-tab snapshot across the sidebar and Starred view, and reloads when the tab regains focus/visibility so other clients' changes become visible.

### Activity overview
- Session navigation has no visible Open/Review label; its accessible name retains the navigation intent. Read, Later and pause/resume controls use small 11px link-style text stacked vertically inside one narrow outlined box to the right, outside the navigation button. Each action remains a separate keyboard-focusable target at least 24px high; longer labels wrap within the box. Rows without actions reserve no box space, and nested rows retain their indentation. Opening a row still does not mark it read.
- Opening or switching Activity and Starred preserves the shown Files/terminal panel on desktop and tablet, without changing its selected reader or workspace. Mobile still hides that full-screen panel to reveal the overview list. Git Explorer retains its separate panel-opening behavior.
- The Activity button triages **Pi Web-managed** sessions/subagents only. `/api/agent/running` adds registry-only `attention` (actual pending blocking extension UI) and the newest 1,000 distinct settled completions plus review receipts from `~/.pi/agent/pi-web/activity-review.json`. Never create wrappers or subscribe to every session to populate the overview; disk-only Pi CLI/Herdr activity cannot be classified as working or blocked.
- `SessionSidebar` owns the existing visible-tab poll and passes attention, running, and server-derived review markers to `AppShell`. Needs you overrides working; a current run overrides an older unread marker. Every settled Pi Web run is recorded even when subagent push/sound notifications are suppressed, so short runs still enter Ready to review. Only explicit read actions acknowledge Ready to review items: the per-row **Read** action or **Mark all subagents as read**, which applies only to ready subagents in the current Activity project filter and visibility scope. Parent sessions and live/blocked/queued/interrupted subagents remain unchanged; opening or selecting a chat leaves the item ready. Acknowledgement POSTs merge per-session timestamps under the same lock as completion recording; the client keeps pending receipts until the server confirms them, drains additional receipts queued during a successful in-flight POST immediately, and retries failed POSTs on the next visible-tab poll. A stale poll cannot resurrect an acknowledged item. Legacy browser timestamps are imported only where a retained completion corroborates them; ID-only unread flags are dropped. A newly observed historical completion must not play a sound; only an observed eligible root running-to-idle transition does.
- **Later** defers an exact completion or pending blocking request without acknowledging/answering it. Optional bounded `laterRuns` receipts extend the version-1 activity ledger (old files default to none), use the same locked atomic writer and validated endpoint (`op: "later"`), and merge monotonically across clients. The sidebar retains optimistic pending deferrals until confirmed and retries failed writes with the visible-tab poll. Read takes precedence; a newer completion is Ready to review again. Exact request-ID receipts (`laterRequests`, independently bounded to 1,000 and defaulting to empty in old files) use `op: "later-request"`; the endpoint corroborates each ID with registry-only live attention, without creating wrappers. Polling reconciles pending request receipts against active IDs, so an old/completion deferral never hides a new question. Deferred attention appears in Later with the same yellow dot, request details and answer navigation; it offers no Read action. Poll confirmation also recovers availability after a persisted write whose response was lost. The Later section follows Ready to review and offers Read only for completed results, but is excluded from bulk ready-subagent acknowledgement. Archived roots and descendants remain eligible for every actionable section; archive state alone never creates activity and project concealment still applies.
- **Pause / Pausing… / Resume** prepares managed main sessions and nested subsessions for restart. Current tools finish; previously submitted input drains or is saved as explicitly undelivered full-envelope context. Waiting cards are saved and cancelled so the agent can ask again later. Paused is not completion or Read/Later acknowledgement. Pause state survives restart, but startup never sends a model request. Resume sends a new literal continuation message to a main session with paused-child IDs/tasks/partial results and cancelled-card context, not a restored execution or old approval. Children have no Resume button; Open main session navigates to their parent conversation. Pausing one child does not automatically pause its otherwise working parent; the child's partial report is saved without triggering a parent turn. Parent Pause includes active descendants. Both All controls are global, including concealed projects, regardless of the Activity filter. The ordinary sidebar poll carries compact pause state without card bodies; no family-wide startup/SSE is added. Failures/partial bulk outcomes and unconfirmed restart intent remain visible. See [session contracts](session-internals.md#cooperative-pause-and-explicit-continuation).
- `lib/activity.ts` uses `workspaceKeyOf` for project identity, and nests a subagent when its parent shares the same section. The optional Queued section uses only live subagent queue IDs; an on-disk `queued` status after a server restart is not proof of a live queue. `ActivityOverview` only lists/navigates: the single selected `ChatWindow` still owns SSE, question replay, and answer submission. Mobile hides the list while viewing a chat but keeps it mounted so Back preserves its filter and scroll position.

Initial URL-session adoption is background restoration, not explicit navigation: it must not close Activity, Starred or Git Explorer opened while the session catalogue was loading. `AppShell.handleSidebarSelectSession` preserves overview state for `isRestore`, while explicit sidebar selection still closes it. The remembered-workspace cancellation token owns a separate restore flow; it is not a substitute for this distinction.

### Worktrees and project grouping
- `lib/worktree.ts` resolves linked worktree top-levels back to the main repo `projectRoot`; `listAllSessions()` attaches that to each `SessionInfo` so all worktrees for one repo are grouped together in the sidebar.
- Worktree operations are served by `/api/worktrees` and guarded by the same allowed-root rules as `/api/files`.
- New worktrees are created under `<repoRoot>-worktrees/<sanitized-branch>` only after selecting a local base branch and its full expected tip. Explicit `create` refuses an existing branch; explicit `attach` requires an existing local branch and its full expected tip. Neither silently uses remote-tracking refs or an implicit checkout HEAD. Source and any checked-out base must be clean (including untracked files). Ref tips are rechecked, but external Git writers may still race.
- Removing a dirty worktree returns `409` with `{ dirty: true }` so the UI can ask before retrying with `force`.
- Sessions whose cwd points at a removed worktree are inferred back into the main project instead of becoming a phantom project row. The separate Sidebar session-worktree filter also lists saved missing directories without selecting/admitting them as cwd. Unknown project ownership never grants automatic recovery; inaccessible directories are unavailable, not missing. Project session actions recover missing roots/subtrees (with descendants, including archived history) to a verified primary checkout; bulk Move reuses the ordinary session mover, not checkout movement or project-settings migration.
- git prints POSIX-style absolute paths even on Windows, so every path read out of git goes through `toNativePath()` (`lib/paths.ts`) before it is compared or returned. Compare paths with `samePath()`, never `===` — raw equality made `isTopLevel` permanently false on Windows and hid the worktree switcher entirely. Branch names are not paths and must keep their forward slashes. Browser code cannot apply Node path rules, so `/api/worktrees` resolves `currentWorktreePath` server-side; the sidebar must use that identity for highlighting and removal fallback.

### Missing-folder session viewing

Session catalogue/detail metadata includes advisory `cwdState` (`present`, `missing`, `unavailable`), classified with the existing directory-state helper: only `ENOENT` is missing; permission errors and non-directories are unavailable. It grants no roots or operation permission. Known missing/unavailable chats remain history-only: preserve their actual cwd and saved history, omit the working composer/account control and automatic model/trust/worktree/file/Git probes, and do not warm/reopen an SDK wrapper or renew an SSE lease. A visible status directs the user to the existing explicit Move action; no parent/server cwd is substituted. Existing terminals/files retain their separate ownership.

Subagent links obtain current detail metadata before selection because cleanup can remove an isolated checkout after a catalogue row was captured. A stale present catalogue row cannot readmit a selected known-missing cwd; an explicit reselect/reload or Move can refresh admission. This is a UI snapshot, not a filesystem lock: external changes can race observation, and server routes keep their existing independent guards. Transient/legacy clients without this metadata retain their existing behavior. Actual history navigation/reload and a request sentinel are covered by the packaged Activity suite.

### Git Explorer
- The top-bar **Git Explorer** icon opens a wide graph/detail panel beside chat; it follows the sidebar's effective checkout (`AppShell.activeCwd`), even when an open chat keeps its own saved `cwd`. `GitExplorerPanel` is keyed by that checkout; branch changes, refreshes and checkout changes clear detail and abort stale reads. `AppShell` owns transient whole-Explorer expansion: a fixed host fills the non-mobile app viewport without changing the panel key or React parent. Covered sibling regions become inert, never its center ancestor. Expand/restore preserve mounted graph/detail, immutable review state and saved pane widths; Close, leaving Explorer or entering mobile resets expansion. Explorer contains Tab traversal and consumes restore Escape before the global agent-stop shortcut, while native per-file Wide view retains first refusal. Close restores focus to the top-bar trigger. No browser Fullscreen API or persisted expansion preference. The branch picker defaults to the checked-out branch and browses other **local branches only**, without checking out. Local tags decorate their commit rows separately from branches; they are display metadata, never history-root authority or checkout actions. Its GET-only `/api/git/explorer` authorizes the physical checkout root against allowed file roots, captures an exact local branch tip for bounded `--topo-order` history pages, rechecks that branch for pagination/detail/patch/context reads and limits commits to that tip's reachable objects. Legacy checkout-HEAD-only requests remain bound to HEAD. Patches/context compare immutable first-parent/commit objects; Explorer never uses session integration policy, uncommitted files or a remote. `GitCommitViewer` has separate copy controls for full commit ID and message. `GitPatchStack` has collapsible sections (first expanded), one shared split/unified/raw and wrap toolbar, and lazy committed-patch reads capped at three concurrent requests. **Expand all files / Collapse all files** affect sections, never eagerly fetch full context. Collapsed renderers unmount; off-screen expanded sections defer reads/rendering. `CommittedPatchDiff` shares virtualized Pierre `CodeView` (`@pierre/diffs` remains 1.5.1) across Explorer, Files and approvals/receipts: per-file full/context and keyboard gap controls, change navigation, clean Before/After, literal case-insensitive search/side-aware line jump, wrapping and Wide view. Escape closes Wide view and restores focus without answering a live approval. Parsed/context/expansion/version/anchor state stays local across file collapse/layout, scoped to the exact commit view, card or working revision; only split/unified/raw and wrap preferences use best-effort browser `localStorage`, never contents/context choices. Files context uses the returned revision and refuses changed HEAD/file state. On mobile graph and details are successive views and diff columns scroll inside the panel. The active-lane algorithm adapts binaryplease/git-graph with attribution in `lib/git-graph-layout.LICENSE`; do not bring over its Bun server or checkout actions. See [docs/worktrees.md](worktrees.md) for controls/limits and [docs/git-workflow-plugin.md](git-workflow-plugin.md#optional-full-file-patch-context) for optional snapshot/receipt context.

### Agent-created ordinary sessions

The enabled-by-default Session Launch plugin exposes `start_session` to ordinary coding sessions, never Chat-only or subagent callers. It uses generic scoped settings/cards/receipts but a separate ordinary-session host: no fork history, subagent family, copied overrides or completion report. Default Ask approves an exact literal prompt and resolved configuration; Request changes returns bounded feedback without launching. Destination-project policy governs foreign launches. The creator receipt links forward and `pi-web:session-spawn` gives the child a stable “Started by…” backlink, with a created-ID check preventing false fork/clone attribution. ## Shared project acceptance

The default-off bundled Acceptance plugin has one global Enabled switch in Settings → Plugins; profile permissions cannot override it. Disabling hides model tools, refuses new requests and cancels not-started queue entries, including across rapid re-enable. Already-started supervisors drain normally. The Acceptance toolbar dialog remains available for retained history, profile configuration and browser status/cancel/recovery, and follows the selected checkout independently of the selected conversation. Private named profiles declare argv, captured input roots, coverage labels, resource estimates and model Ask/Allow/Deny. `lib/acceptance/` owns one cooperative heavy-run slot across projects in the same agent directory, immutable-input in-flight sharing, durable status and owned Linux supervision. It does not intercept Bash or confer Git/deployment authority. Session tools cannot edit profiles. Browser recovery reconciles lost/unknown ownership without replaying work or manufacturing a pass; Stop/Pause/wait cancellation never silently cancels an independently admitted project job. See [Shared project acceptance](acceptance.md) and [ADR 0031](adr/0031-project-acceptance-coordination.md).

## Git operations

Managed Workflow tools, settings, approvals and injected guidance remain removed; private Workflow data/history is untouched. Independent Git Explorer, read-only status/diffs and standalone worktrees remain. Ordinary coding/shell Git usage follows applicable user/repository instructions and never depends on plugin settings. The optional default-disabled Git Workflow plugin uses the static `lib/plugins/registry.ts` composition root and Pi extension APIs, not the removed framework. Core chat/session code imports only generic plugin extensions/cards; Git semantics stay in `plugins/git-workflow/`. Private schema-versioned overrides inherit built-in → global → selected canonical-repository project → session, with global-only enablement. Session overrides apply only when the selected repository matches the session's own repository and the override's stored binding; cross-project operations never borrow caller/session settings. Presets change workflow choices only, each of which supports Ask via `ask_user`. SDK-context identity and validated saved headers own session identity; forks/subagents do not copy overrides and moves deactivate mismatched bindings. Request-local `pi-web:git-policy/v1` guidance and read-only `git_policy` expose current choices without persisting policy instructions into conversation history. Live saves update tools through Pi registration/hidden exposure and cancel waiting approvals; started native effects settle honestly. No managed tasks, legacy evidence protocols, CLI dependency or arbitrary code loader. Saved intent does not override stronger instructions unless those instructions explicitly recognize the harness contract. Both Ask and Allow require durable generic operation receipts before checks/effects and after settlement; policy authorization never means user acceptance or execution success. Unsettled stages remain unknown. `git_cleanup` has separate default-Ask permission, exact integration/feature IDs, bounded content inventories and managed-directory admission protection. `approvedArtifactRoots` is a reusable user-owned allowlist of exact literal worktree-relative generated **files or directories**, including slash-delimited nested paths (no defaults/globs or inherited parent authority). Worktree removal also proposes exact ignored artifacts at any depth even with `artifactRoots: []`; explicit roots may add generated paths, but neither discovery nor arguments grant authority. Any unlisted artifact requires one live cleanup-card approval even under Allow; Ask combines artifact and operation consent in that same card, without changing settings. Record effective Ask/user-approved provenance, not Policy authorized, for this exception. Freeze paths before approval; do not discover new artifacts during effects. Unselected unignored untracked files, tracked/dirty source, changed resources, symbolic refs, symlink roots/ancestors, overlapping roots, main/caller/active checkouts and mounts are refused; partial effects are recorded without rollback. Nested artifacts may share tracked directory parents without selecting them; never promote ignored children to source parents. Linux no-follow directory handles bind selected-root ancestors across deletion; unsupported platforms/proc configurations refuse nested cleanup before approval. Discovery does not bypass explicit-child validation. Fingerprints tolerate direct-parent size/timestamp changes only after completed approved child deletions, preserving source contents, structure, identity and unaffected metadata. See `docs/adr/0017-cleanup-artifact-approval.md` and its nested-path revision `docs/adr/0019-nested-cleanup-artifacts.md`. Target advancement alone does not stale cleanup if pinned integration remains reachable. External writers are not locked out. Original strict `removeWorktree` still retains branches and refuses ignored files; the CLI is unchanged. See [docs/git-workflow-plugin.md](git-workflow-plugin.md) for tools, checks, unsupported repository states and separate plugin test commands.

### File access allow-list
- `/api/files` is intentionally not a general filesystem browser. Allowed roots come from session cwds, their resolved project roots, `~/pi-cwd-*`, and roots explicitly added with `allowFileRoot()`.
- `/api/cwd/validate`, `/api/default-cwd`, and `/api/worktrees` call `allowFileRoot()` when they make a new location browsable.
- External session-reference reads use explicit sources, not recursive transcript strings: user/assistant text, known coding-call path fields/commands, recognized coding/subagent result text, documented shell output paths and typed host background reports. System/context/receipt/custom metadata, thinking/images and unknown tool-result text do not authorize files. Literal filenames use `samePath` without URI decoding or fragment/source-suffix stripping; prose links retain their navigation conventions. Legacy unnamed results resolve only through ancestor calls, never siblings. This remains session-wide historical, read-only access; coding output text is a compatibility concession, not a general prompt-injection defense. See [ADR 0026](adr/0026-request-and-file-reference-boundaries.md).
- Allowed roots are stored slash-normalized, but that is a Set-key convention, not a correctness requirement: `isPathWithinRoots()` (`lib/path-security.ts`, the single implementation behind `isFilePathAllowed()`) re-resolves and case-folds both sides, so either path form authorizes correctly. Keep that one implementation — it is the security boundary.
- A UNC cwd (`\\host\share\dir`) must survive the `/api/files/[...path]` round-trip. `encodeFilePathForApi()` folds the `//` root into the first segment (`%2F%2Fhost`) because a literal `//` URL prefix is 308-normalized away before routing; `filePathFromApiSegments()` decodes it back. Never split UNC paths into segments and rejoin them — that silently turns `\\host\share` into the relative-looking `host/share` and every allow-check fails with 403.

### Chat file and source-line links
- Prefer absolute filesystem destinations in chat, especially across repositories/worktrees: `[file](/absolute/path/file.ts#L36)`. Never prepend the Pi Web hostname/origin. Relative chat links resolve from the session cwd; Markdown previews resolve from the document directory with the session cwd as their relative-link boundary (or the document directory when no cwd is available). Relative paths cannot escape that boundary. Absolute paths still pass the existing server file-access checks; recognizing a link does not authorize access.
- `resolveLocalFileLink()` distinguishes accepted local paths, rejected relative links (outside the relative root or missing a base), and ordinary web/app links. When an in-app file handler is available, `MarkdownBody` and Markdown previews render rejected links with shared `BlockedFileLink` buttons: no navigable href, a hover explanation and keyboard/touch-expandable status text suggesting an absolute path. Encoded traversal follows the same normalization. External/app URLs and the path-only `resolveLocalFileHref()` contract remain unchanged. Inline-code references that cannot resolve stay plain code.
- `lib/local-file-link-guidance.ts` adds deduplicated SDK `promptGuidelines` for ordinary coding sessions and fresh/reopened append-mode coding subagents, independently of user-extension discovery. It covers absolute destinations, relative-link boundaries, known source coordinates and the distinction between filesystem checks and browser verification. Reload retains the host factory. Chat-only and exact replacement profiles are untouched; SDK custom `SYSTEM.md` prefixes continue to replace default rules. Existing wrappers need recreation after deploying this new factory; source changes alone do not update the installed service or repair old documents.
- Chat Markdown links may point to a local file and one-based source line: `[myFunction](src/file.ts#L36)`, `[range](src/file.ts#L36-L48)`, `[line](src/file.ts:36)` or `[location](src/file.ts:36:5)`. Bare inline-code references such as `src/file.ts:36` and `README.md:25` also become clickable; ordinary symbol names and fenced code blocks do not. The model must supply a known file/line, not an invented symbol anchor. Columns are accepted metadata; the viewer jumps/highlights at line granularity. PDF `#page=N` links remain separate.
- `lib/file-links.ts` parses locations without changing the existing file-path/access boundary. `MarkdownBody`, `MessageView`, `ChatWindow` and `FileWorkspace` carry source targets through independently identified file views. Every explicit line click performs a fresh jump, including an already-open file or repeated same-line click. Mode/wrap preferences and unsaved drafts survive. Navigation that would replace an in-flight save owner queues until settlement; a viewer reactivated while another instance saves stays read-only, while the original owner can retain further typing. A pending target survives tab deactivation until reached or found beyond EOF; once handled, ordinary tab activation restores the saved scroll instead of replaying the link.
- PDF page commands, including a repeat of the same `#page=N`, reload only the native PDF embed; the file-view host stays stable. Other interactive embeds do not acquire navigation-driven remounts.
- `FileViewer` scrolls only its file pane and highlights source lines/ranges. It loads bounded text chunks until the requested range is available and reports an out-of-file line instead of silently choosing another source line. Targets refer to current saved content, not immutable historical files or unsaved draft coordinates; dirty drafts stay available through Edit, with a visible saved-file notice. Initial Diff/HTML Preview switches to Source for the jump, but later manual mode choices are not locked out.
- Markdown remains rendered by default: parser-owned source positions identify the smallest containing paragraph, heading, list item, code/math block or table row. Blank/hidden lines use the nearest rendered block; a document with no rendered blocks falls back to Source. `normalizeDisplayMathWithSourceMap` preserves original file coordinates across math normalization and frontmatter, and `rehypeMarkdownSourceLines` runs after sanitization/before KaTeX, retaining stable code/math wrappers. Source shows exact lines; rendered ranges highlight the starting block. Markdown-preview file links propagate the same source targets. Same-document heading fragments, raw anchors and footnotes scroll within their own `.markdown-body`, without changing app history. Heading slugs are post-sanitize data attributes, not page-global IDs; duplicate headings receive deterministic suffixes. Cross-file source coordinates still use the documented `#L…` contract; automatic symbol lookup, persisted browser permalinks and historical line rebasing are not implemented.

Initial rendering/scrolling performs no notebook Git reads; collapse aborts/unmounts and reopening reloads under fresh authority.

- `ReviewNavigationContext` starts a shared reveal generation before asynchronous validation. AppShell accepts only the latest command in its originating session/cwd scope; close, return and other overview navigation invalidate pending commands. A temporary referenced-repository Explorer has matching initial graph/detail branch/tip/commit, an explicit label and Return action, without changing sidebar/session/file/terminal identity. Return restores keyboard focus inside Explorer. Off-page commits have exact detail plus a load-older notice; no unbounded auto-pagination.

[Review notebooks](review-notebooks.md) owns authoring; [ADR 0029](adr/0029-markdown-review-notebooks.md) records the boundaries. ### Explicit inline chat media

Settled user/assistant chat renders local `![label](recording.wav)` / `![label](demo.webm)` embeds as labelled **Load audio/video** controls. No media element, poster, metadata fetch or watcher exists before activation; loading exposes native controls, never autoplay. ### File preview tables and probe eligibility

CSV/TSV support a dependency-free, rendered-first table preview under the existing Git-diff/restored/explicit-mode rules; source-line targets win. Quoting, doubled quotes, multiline records, BOM/CRLF, ragged rows and CSV delimiter detection are supported; TSV always uses tabs. The first record is the header and the gutter names record-start source lines. Only viewport rows mount; an incomplete last record of a loaded prefix waits for more content. This is row virtualization, not column virtualization or a total parsing/memory bound. CSV `#L…` targets open Source.

Text-read JSON carries advisory `probeEligibility` for automatic edit/Git probes, narrowed by the existing lexical/physical roots and optional validated `viewerCwd`. Reference-only reads return both false; missing root-authorized files retain Git eligibility through their nearest surviving physical parent, including deleted directories. Unknown hints fail closed for automatic probes. They never authorize an operation: edit/save/Git endpoints retain all original checks. FileViewer waits for the read hint, guards callbacks by file/session/cwd and invalidates watcher continuations on cleanup; forbidden probes do not become a console-error exemption. ### Web password throttling
- `lib/auth-throttle.ts` is deliberately global, not per-IP: Next 16 route handlers have no socket address and `x-forwarded-for` is spoofable, while the server binds `127.0.0.1` for a single operator. Failures double the delay (1s → 60s cap) for everyone; a success or 5 idle minutes resets it. The reset window must stay longer than the max delay or waiting out one block restarts the burst.
- State lives on `globalThis` under `Symbol.for("pi-web:auth-throttle")` so it survives hot reload and is shared by every module instance. Tests reset it with `recordAuthSuccess()`.
- `POST /api/web-auth` and every `Authorization: Basic` header on `/api/*` share the counter; `proxy.ts` checks Basic before its `/api/web-auth` exemption, so `GET /api/web-auth` is not an unthrottled password oracle. A valid session cookie is checked first and is never blocked. While blocked, Basic gets `429` even with the right password (otherwise the answer leaks), and a Basic success does not reset the counter: Basic clients authenticate on every request, so a reset would restart an interleaved guesser at the base delay. The proxy and route handlers share the `globalThis` state under both `next dev` and `next start` (checked by failing one and observing `429` on the other).
