# Feature implementation contracts

Implementation reference moved from `AGENTS.md`; repository-relative code paths remain unchanged. Read the relevant section before modifying that area. Focused user guides and ADRs linked below retain their existing scopes.

### Starred sessions
- Stars live in `~/.pi/agent/pi-web/starred-sessions.json`, not in session files or the browser's long-term storage. `POST /api/starred-sessions` applies idempotent per-ID set/unset changes under a file lock; legacy localStorage lists are imported as a union then removed only after success. A browser with an old, not-yet-imported list may reintroduce a previously removed star on its first visit.
- `useStarredSessions` shares one browser-tab snapshot across the sidebar and Starred view, and reloads when the tab regains focus/visibility so other clients' changes become visible.

### Activity overview
- The Activity button triages **Pi Web-managed** sessions/subagents only. `/api/agent/running` adds registry-only `attention` (actual pending blocking extension UI) and the newest 1,000 distinct settled completions plus review receipts from `~/.pi/agent/pi-web/activity-review.json`. Never create wrappers or subscribe to every session to populate the overview; disk-only Pi CLI/Herdr activity cannot be classified as working or blocked.
- `SessionSidebar` owns the existing visible-tab poll and passes attention, running, and server-derived review markers to `AppShell`. Needs you overrides working; a current run overrides an older unread marker. Every settled Pi Web run is recorded even when subagent push/sound notifications are suppressed, so short runs still enter Ready to review. Only explicit read actions acknowledge Ready to review items: the per-row **Read** action or **Mark all subagents as read**, which applies only to ready subagents in the current Activity project filter and visibility scope. Parent sessions and live/blocked/queued/interrupted subagents remain unchanged; opening or selecting a chat leaves the item ready. Acknowledgement POSTs merge per-session timestamps under the same lock as completion recording; the client keeps pending receipts until the server confirms them, drains additional receipts queued during a successful in-flight POST immediately, and retries failed POSTs on the next visible-tab poll. A stale poll cannot resurrect an acknowledged item. Legacy browser timestamps are imported only where a retained completion corroborates them; ID-only unread flags are dropped. A newly observed historical completion must not play a sound; only an observed eligible root running-to-idle transition does.
- `lib/activity.ts` filters archived families, uses `workspaceKeyOf` for project identity, and nests a subagent when its parent shares the same section. The optional Queued section uses only live subagent queue IDs; an on-disk `queued` status after a server restart is not proof of a live queue. `ActivityOverview` only lists/navigates: the single selected `ChatWindow` still owns SSE, question replay, and answer submission. Mobile hides the list while viewing a chat but keeps it mounted so Back preserves its filter and scroll position.

### Worktrees and project grouping
- `lib/worktree.ts` resolves linked worktree top-levels back to the main repo `projectRoot`; `listAllSessions()` attaches that to each `SessionInfo` so all worktrees for one repo are grouped together in the sidebar.
- Worktree operations are served by `/api/worktrees` and guarded by the same allowed-root rules as `/api/files`.
- New worktrees are created under `<repoRoot>-worktrees/<sanitized-branch>` only after selecting a local base branch and its full expected tip. Explicit `create` refuses an existing branch; explicit `attach` requires an existing local branch and its full expected tip. Neither silently uses remote-tracking refs or an implicit checkout HEAD. Source and any checked-out base must be clean (including untracked files). Ref tips are rechecked, but external Git writers may still race.
- Removing a dirty worktree returns `409` with `{ dirty: true }` so the UI can ask before retrying with `force`.
- Sessions whose cwd points at a removed worktree are inferred back into the main project instead of becoming a phantom project row.
- git prints POSIX-style absolute paths even on Windows, so every path read out of git goes through `toNativePath()` (`lib/paths.ts`) before it is compared or returned. Compare paths with `samePath()`, never `===` — raw equality made `isTopLevel` permanently false on Windows and hid the worktree switcher entirely. Branch names are not paths and must keep their forward slashes. Browser code cannot apply Node path rules, so `/api/worktrees` resolves `currentWorktreePath` server-side; the sidebar must use that identity for highlighting and removal fallback.

### Git Explorer
- The top-bar **Git Explorer** icon opens a wide graph/detail panel beside chat; it follows the sidebar's effective checkout (`AppShell.activeCwd`), even when an open chat keeps its own saved `cwd`. `GitExplorerPanel` is keyed by that checkout; branch changes, refreshes and checkout changes clear detail and abort stale reads. `AppShell` owns transient whole-Explorer expansion: a fixed host fills the non-mobile app viewport without changing the panel key or React parent. Covered sibling regions become inert, never its center ancestor. Expand/restore preserve mounted graph/detail, immutable review state and saved pane widths; Close, leaving Explorer or entering mobile resets expansion. Explorer contains Tab traversal and consumes restore Escape before the global agent-stop shortcut, while native per-file Wide view retains first refusal. Close restores focus to the top-bar trigger. No browser Fullscreen API or persisted expansion preference. The branch picker defaults to the checked-out branch and browses other **local branches only**, without checking out. Local tags decorate their commit rows separately from branches; they are display metadata, never history-root authority or checkout actions. Its GET-only `/api/git/explorer` authorizes the physical checkout root against allowed file roots, captures an exact local branch tip for bounded `--topo-order` history pages, rechecks that branch for pagination/detail/patch/context reads and limits commits to that tip's reachable objects. Legacy checkout-HEAD-only requests remain bound to HEAD. Patches/context compare immutable first-parent/commit objects; Explorer never uses session integration policy, uncommitted files or a remote. `GitCommitViewer` has separate copy controls for full commit ID and message. `GitPatchStack` has collapsible sections (first expanded), one shared split/unified/raw and wrap toolbar, and lazy committed-patch reads capped at three concurrent requests. **Expand all files / Collapse all files** affect sections, never eagerly fetch full context. Collapsed renderers unmount; off-screen expanded sections defer reads/rendering. `CommittedPatchDiff` shares virtualized Pierre `CodeView` (`@pierre/diffs` remains 1.5.1) across Explorer, Files and approvals/receipts: per-file full/context and keyboard gap controls, change navigation, clean Before/After, literal case-insensitive search/side-aware line jump, wrapping and Wide view. Escape closes Wide view and restores focus without answering a live approval. Parsed/context/expansion/version/anchor state stays local across file collapse/layout, scoped to the exact commit view, card or working revision; only split/unified/raw and wrap preferences use best-effort browser `localStorage`, never contents/context choices. Files context uses the returned revision and refuses changed HEAD/file state. On mobile graph and details are successive views and diff columns scroll inside the panel. The active-lane algorithm adapts binaryplease/git-graph with attribution in `lib/git-graph-layout.LICENSE`; do not bring over its Bun server or checkout actions. See [docs/worktrees.md](worktrees.md) for controls/limits and [docs/git-workflow-plugin.md](git-workflow-plugin.md#optional-full-file-patch-context) for optional snapshot/receipt context.

### Agent-created ordinary sessions

The enabled-by-default Session Launch plugin exposes `start_session` to ordinary coding sessions, never Chat-only or subagent callers. It uses generic scoped settings/cards/receipts but a separate ordinary-session host: no fork history, subagent family, copied overrides or completion report. Default Ask approves an exact literal prompt and resolved configuration; Request changes returns bounded feedback without launching. Destination-project policy governs foreign launches. The creator receipt links forward and `pi-web:session-spawn` gives the child a stable “Started by…” backlink, with a created-ID check preventing false fork/clone attribution. See [Session Launch](session-launch.md) for configuration, permission/intent boundaries, admission checks and SDK/browser verification.

## Git operations

Managed Workflow tools, settings, approvals and injected guidance remain removed; private Workflow data/history is untouched. Independent Git Explorer, read-only status/diffs and standalone worktrees remain. Ordinary coding/shell Git usage follows applicable user/repository instructions and never depends on plugin settings. The optional default-disabled Git Workflow plugin uses the static `lib/plugins/registry.ts` composition root and Pi extension APIs, not the removed framework. Core chat/session code imports only generic plugin extensions/cards; Git semantics stay in `plugins/git-workflow/`. Private schema-versioned overrides inherit built-in → global → selected canonical-repository project → session, with global-only enablement. Session overrides apply only when the selected repository matches the session's own repository and the override's stored binding; cross-project operations never borrow caller/session settings. Presets change workflow choices only, each of which supports Ask via `ask_user`. SDK-context identity and validated saved headers own session identity; forks/subagents do not copy overrides and moves deactivate mismatched bindings. Request-local `pi-web:git-policy/v1` guidance and read-only `git_policy` expose current choices without persisting policy instructions into conversation history. Live saves update tools through Pi registration/hidden exposure and cancel waiting approvals; started native effects settle honestly. No managed tasks, legacy evidence protocols, CLI dependency or arbitrary code loader. Saved intent does not override stronger instructions unless those instructions explicitly recognize the harness contract. Both Ask and Allow require durable generic operation receipts before checks/effects and after settlement; policy authorization never means user acceptance or execution success. Unsettled stages remain unknown. `git_cleanup` has separate default-Ask permission, exact integration/feature IDs, bounded content inventories and managed-directory admission protection. `approvedArtifactRoots` is a reusable user-owned allowlist of exact literal worktree-relative generated **files or directories**, including slash-delimited nested paths (no defaults/globs or inherited parent authority). Worktree removal also proposes exact ignored artifacts at any depth even with `artifactRoots: []`; explicit roots may add generated paths, but neither discovery nor arguments grant authority. Any unlisted artifact requires one live cleanup-card approval even under Allow; Ask combines artifact and operation consent in that same card, without changing settings. Record effective Ask/user-approved provenance, not Policy authorized, for this exception. Freeze paths before approval; do not discover new artifacts during effects. Unselected unignored untracked files, tracked/dirty source, changed resources, symbolic refs, symlink roots/ancestors, overlapping roots, main/caller/active checkouts and mounts are refused; partial effects are recorded without rollback. Nested artifacts may share tracked directory parents without selecting them; never promote ignored children to source parents. Linux no-follow directory handles bind selected-root ancestors across deletion; unsupported platforms/proc configurations refuse nested cleanup before approval. Discovery does not bypass explicit-child validation. Fingerprints tolerate direct-parent size/timestamp changes only after completed approved child deletions, preserving source contents, structure, identity and unaffected metadata. See `docs/adr/0017-cleanup-artifact-approval.md` and its nested-path revision `docs/adr/0019-nested-cleanup-artifacts.md`. Target advancement alone does not stale cleanup if pinned integration remains reachable. External writers are not locked out. Original strict `removeWorktree` still retains branches and refuses ignored files; the CLI is unchanged. See [docs/git-workflow-plugin.md](git-workflow-plugin.md) for tools, checks, unsupported repository states and separate plugin test commands.

### Project manager resource discard

The no-chat manager uses the generic project-action host, not a fabricated session.
Its browser-only `discardResources` permission defaults to Ask; both Ask and Allow
require exact live confirmation. Any containment state/no target can be reviewed,
but source/physical/target/activity/artifact guards still apply. Clean valid detached
subjects remove only their worktree and warn about commit retention. The Git plugin
supplies loss evidence and bounded `requiredAcknowledgment` only for unproven branch
deletion; the generic host binds the frozen card to an operation/nonce digest and
requires durable matching affirmative consent before release. Checkbox state resets
by context/operation/digest; saved acceptance is read-only and never restart authority.
Unsupported requirement-bearing session approvals fail closed. Agent cleanup remains
integrated-only; completed-feature Keep preferences do not veto separately confirmed
manual discard. See [Worktrees](worktrees.md#explicit-removal-and-recovery),
[Git plugin API](git-workflow-plugin.md#standalone-project-removal-api) and
[ADR 0022](adr/0022-browser-resource-discard.md).

### Size-independent Git operation review

New Git operations save exact review bundles once in private `pi-web/reviews/`; compact cards and stage receipts reference them. Never raise the inline card cap to accommodate a large operation or repeat patches at every receipt stage. Session-scoped review GETs authorize only through saved receipt references (prepared counts), verify integrity and never create wrappers or read current checkouts. Small reviews retain the shared diff/context controls; larger ones use paged inventories/content and streamed exact downloads. Preview limits never remove approval actions or narrow scope. Published bundles are retained without TTL/automatic GC so moves and surviving forks keep history; backups must include them. Git preparation/check output is streamed, Files commits use NUL-delimited pathspec files, and checks have optional explicit `timeoutMs` (zero/absent means none). Cleanup inventories remain complete and cancellable, with spill-to-disk directory sorting instead of fixed total-size/time budgets; existing source/mount/authority protections still apply. See `docs/adr/0018-size-independent-git-reviews.md` and `docs/git-workflow-plugin.md`.

### File access allow-list
- `/api/files` is intentionally not a general filesystem browser. Allowed roots come from session cwds, their resolved project roots, `~/pi-cwd-*`, and roots explicitly added with `allowFileRoot()`.
- `/api/cwd/validate`, `/api/default-cwd`, and `/api/worktrees` call `allowFileRoot()` when they make a new location browsable.
- Allowed roots are stored slash-normalized, but that is a Set-key convention, not a correctness requirement: `isPathWithinRoots()` (`lib/path-security.ts`, the single implementation behind `isFilePathAllowed()`) re-resolves and case-folds both sides, so either path form authorizes correctly. Keep that one implementation — it is the security boundary.
- A UNC cwd (`\\host\share\dir`) must survive the `/api/files/[...path]` round-trip. `encodeFilePathForApi()` folds the `//` root into the first segment (`%2F%2Fhost`) because a literal `//` URL prefix is 308-normalized away before routing; `filePathFromApiSegments()` decodes it back. Never split UNC paths into segments and rejoin them — that silently turns `\\host\share` into the relative-looking `host/share` and every allow-check fails with 403.

### Chat file and source-line links
- Chat Markdown links may point to a local file and one-based source line: `[myFunction](src/file.ts#L36)`, `[range](src/file.ts#L36-L48)`, `[line](src/file.ts:36)` or `[location](src/file.ts:36:5)`. Bare inline-code references such as `src/file.ts:36` and `README.md:25` also become clickable; ordinary symbol names and fenced code blocks do not. The model must supply a known file/line, not an invented symbol anchor. Columns are accepted metadata; the viewer jumps/highlights at line granularity. PDF `#page=N` links remain separate.
- `lib/file-links.ts` parses locations without changing the existing file-path/access boundary. `MarkdownBody`, `MessageView`, `ChatWindow` and `AppShell` carry source targets through file tabs. Every explicit line click performs a fresh jump, including an already-open file or repeated same-line click. Mode/wrap preferences and unsaved drafts survive. Navigation that would replace an in-flight save owner queues until settlement; a viewer reactivated while another instance saves stays read-only, while the original owner can retain further typing. A pending target survives tab deactivation until reached or found beyond EOF; once handled, ordinary tab activation restores the saved scroll instead of replaying the link.
- `FileViewer` scrolls only its file pane and highlights source lines/ranges. It loads bounded text chunks until the requested range is available and reports an out-of-file line instead of silently choosing another source line. Targets refer to current saved content, not immutable historical files or unsaved draft coordinates; dirty drafts stay available through Edit, with a visible saved-file notice. Initial Diff/HTML Preview switches to Source for the jump, but later manual mode choices are not locked out.
- Markdown remains rendered by default: parser-owned source positions identify the smallest containing paragraph, heading, list item, code/math block or table row. Blank/hidden lines use the nearest rendered block; a document with no rendered blocks falls back to Source. `normalizeDisplayMathWithSourceMap` preserves original file coordinates across math normalization and frontmatter, and `rehypeMarkdownSourceLines` runs after sanitization/before KaTeX, retaining stable code/math wrappers. Source shows exact lines; rendered ranges highlight the starting block. Markdown-preview file links propagate the same source targets. Heading fragments, automatic symbol lookup, persisted browser permalinks and historical line rebasing are not implemented.

### Editing open files
- The Files panel offers Edit/Save only for existing, writable UTF-8 text files up to 1 MB in the writable file-root allow-list. `GET ?type=edit` returns a complete bounded snapshot and SHA-256 revision; `PUT ?type=save` checks that revision before a same-directory replacement. Session-referenced paths outside the allow-list remain read-only, even though ordinary GET can show them. Reject symlink targets, escapes, binary/media files and read-only directories; do not use the chunked text preview as a save baseline.
- `AppShell` owns unsaved drafts per file tab because only the active `FileViewer` mounts. Watch events refresh clean content but never overwrite a dirty draft; external edits cause a conflict requiring discard/reload rather than silent overwrite. Saves preserve file mode but replace the inode (including hardlink identity), and external filesystem writers can race the final compare/rename. Browser reload does not persist drafts.

### Plugins and skills
- `/api/plugins` uses pi's `SettingsManager` + `DefaultPackageManager` for global/project package install, remove, update, enable, and disable. Disabling writes empty `extensions/skills/prompts/themes` arrays for that package entry.
- `/api/skills` uses `DefaultResourceLoader` so settings paths, package skills, and project `.agents/skills` are listed the same way the runtime sees them.
- Skill toggling edits only the `disable-model-invocation` frontmatter key on the target `SKILL.md`; keep that surgical so user formatting survives.
- `/api/skills/install` shells through `npx skills add ... --agent pi`; project installs run with the selected cwd.

### Browser-native `ask_user`
- `ask_user` accepts either the legacy `question` form or `title` plus 1–6 ID-based `questions` (`single`, `multiple`, `text`). Batch related independent decisions, never dependent follow-ups. `lib/question-set.ts` validates complete answer sets atomically; the internal `ask_user_batch` request uses the existing pending UI lifecycle. Every batch question has an alternative written main answer and separate additive details, even for freeform answers; optional skip is explicit. `QuestionSetDialog` owns free navigation/review and preserves drafts until confirmed submission; `QuestionSetReview` is also the read-only receipt body. Recommendations are not defaults. Same-tab `sessionStorage` drafts are scoped to session/request/payload, cleared on observed settlement, and bounded to 12 sets/24 hours on load/save. They are never sent to the model; no cross-device or server-restart recovery. See [docs/questions.md](questions.md).
- `lib/ask-user.ts` and `lib/ask-user-extension.ts` adapt the web-relevant contract from pi-ask-user 0.15.0; the upstream MIT license ships as `lib/ask-user.LICENSE`. The terminal package remains separate. Only a recognized `pi-ask-user` extension is suppressed in ordinary Pi Web sessions and extension-enabled subagents so the tool is not registered twice; do not hide unrelated collisions or load the tool in Chat-only mode.
- `AgentSessionWrapper.createExtensionUiContext().askUser()` uses the same pending request/response maps as ordinary extension dialogs. Questions and choices are replayed to reconnecting SSE clients; server-side answer validation, timeout, Stop, and teardown own settlement. `AskUserDialog` in the browser handles the native form, not ANSI custom-UI keystrokes. Live blocking extension requests (`ask_user`, select, confirm, input, editor, plugin cards) render at the chat tail, not in modal overlays. Settlement appends one versioned `pi-web:interaction-receipt` custom session entry with the exact displayed payload and normalized decision, outside model context, before closing the live request. `lib/interaction-receipts.ts` projects recognized receipts into branch-aware UI history; `InteractionReceiptCard` renders them read-only and collapsed by default. Receipt events deduplicate by entry/request ID; SSE connection reconciles missed saved history. Decisions never claim execution success, and historical review never invokes tools. Expansion preferences are not persisted and collapsed historical bodies unmount. Existing entries are not backfilled and SDK HTML export does not render receipts. `BlockingCard` owns their compact shared presentation, bounded scrolling body and fixed footer; collapse retains drafts and nested diff state. Generic plugin card fields/sections remain bounded by `lib/plugins/ui.ts`; Git-specific summaries are supplied by the plugin, never inferred by core from text. The existing request ID, response and close events still own expiry, replay and cancellation; the non-question custom UI panel remains an overlay. Keep response details, redacted events, and tool schema compatible with the installed extension.

### Web password throttling
- `lib/auth-throttle.ts` is deliberately global, not per-IP: Next 16 route handlers have no socket address and `x-forwarded-for` is spoofable, while the server binds `127.0.0.1` for a single operator. Failures double the delay (1s → 60s cap) for everyone; a success or 5 idle minutes resets it. The reset window must stay longer than the max delay or waiting out one block restarts the burst.
- State lives on `globalThis` under `Symbol.for("pi-web:auth-throttle")` so it survives hot reload and is shared by every module instance. Tests reset it with `recordAuthSuccess()`.
- `POST /api/web-auth` and every `Authorization: Basic` header on `/api/*` share the counter; `proxy.ts` checks Basic before its `/api/web-auth` exemption, so `GET /api/web-auth` is not an unthrottled password oracle. A valid session cookie is checked first and is never blocked. While blocked, Basic gets `429` even with the right password (otherwise the answer leaks), and a Basic success does not reset the counter: Basic clients authenticate on every request, so a reset would restart an interleaved guesser at the base delay. The proxy and route handlers share the `globalThis` state under both `next dev` and `next start` (checked by failing one and observing `429` on the other).

### Chat appearance
- Messages and the composer use the full available chat pane width by default, retaining padding, the desktop minimap and any open side panels. The composer width button switches to the reading column (820px by default) and back; it remains visible outside mobile More controls and does not change the draft or session.
- `hooks/useChatAppearance.ts` shares the browser-tab appearance snapshot. `pi-chat-content-full-width` remembers the mode (only `false` opts into reading width), independently of the existing `pi-chat-content-width` numeric preference and font size. Existing numeric preferences remain available without overriding the new full-width default. Settings offers the same mode switch; adjusting or resetting the numeric reading width activates reading mode. `--chat-content-max-width` is `none` in full-width mode, not a larger fixed cap. Persistence is best-effort when browser storage is unavailable.

### Completion sound
- `hooks/useAudio.ts` stores the toggle in `localStorage` as `pi-sound-enabled` and reuses one `AudioContext`.
- Browser autoplay policy means sound must be unlocked from a user gesture; `ChatInput` calls the unlock hook from interactive controls, and `ChatWindow` plays the tone from `onAgentEnd`.
