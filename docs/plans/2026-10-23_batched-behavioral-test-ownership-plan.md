## Architecture and batching

- Inventory the remaining candidate families before assigning migrations. Separate
  genuine architecture/import guards, SSR/presentation contracts and actual native
  tests from brittle behavior assertions over source spelling/extracted copies.
- Directly import production rules for decision matrices. Extract instance-owned
  orchestration only where an actual lifecycle boundary warrants it; no universal
  god store or mandatory controller framework.
- Mount the actual production component/hook for React/effect/current-closure
  obligations. External transport/time/storage/native capabilities may be controlled;
  the state machine and production composition may not be reimplemented in a host.
- For each changed family, record exact old obligations, new primary owner and
  retained native/browser/default bridges. Behavioral green plus meaningful runtime
  red and independent disposition review precede assertion retirement.
- Batch compatible families and focused selections under one frozen source and
  coordinator. Keep reviewable commits by contract; perform complete acceptance only
  when the composed source settles, then rebase/reassess exact inputs before local
  unsigned nonFF integration. The exact-action merge/cleanup gates remain separate.
