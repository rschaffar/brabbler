# English interface messages

Brabbler's interface is English-only. The app and static demo ship only the
English catalog in `lib/i18n/messages/en.ts`; there is no interface language
selector, browser-language detection, or saved language preference. Legacy
`pi-locale` values are ignored. The document language is always `en`.

The small internal message layer remains to centralize UI copy and interpolate
runtime values without rewriting every component. `useI18n()` returns `t` and
the fixed `en` formatting locale; it has no locale setter or selectable list.
Components must remain below `I18nProvider`.

```tsx
const { t } = useI18n();
return <span>{t("sidebar.changedFiles", { count: changedFileCount })}</span>;
```

## Adding or changing UI text

1. Add a stable feature-namespaced key to `lib/i18n/messages/en.ts`.
2. Use `t("namespace.key")` for visible text, titles, accessible labels and
   placeholders, with interpolation for counts, names and paths.
3. Keep product/model/provider names, commands, paths, user content, tool output
   and server-provided error details unchanged. Do not match server error text
   to translate it.

Missing messages return the key and produce a development warning. Date and
relative-time chrome uses English formatting while retaining local time zones.
Push notification fallback titles and bodies are English even for subscriptions
saved with a former interface locale; actual session names remain unchanged.
The demo always selects English tutorial content, independently of browser or
stored preferences.

## Generated session titles

The **Generated title language** setting is separate from the interface language.
It still supports automatic language matching, English, German, Simplified Chinese
and Traditional Chinese. Title-language storage, APIs and generation are unchanged.
An English interface does not restrict conversation languages or code highlighting.

## Verification

Follow [Testing](testing.md) for the common baseline and browser acceptance.
Catalog/format tests live in `lib/i18n/`; settings tests assert the absence of an
interface language selector and preservation of the title-language setting.
Browser acceptance exercises non-English browser locales with legacy `pi-locale`
values, English controls, and reloads. Do not run a production build during normal
development.
